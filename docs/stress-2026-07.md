# Stress test — netdust-flow + worktable backend (2026-07-24)

Six runs across five domains, driven through the **real** runtime
(`hooks/loop-gate.py` → `bin/flow-check.py` → `.flow-journal.jsonl` →
`bin/flow-eval.py`) — not a simulation. The goal was to force *different*
outcomes and find where the engine holds vs where it strains the model.
Records live in `records/<domain>/`; journals + `flow-eval` are the
evidence.

## Runs

| Domain (use case) | Flow | Outcome driven | Terminal |
|---|---|---|---|
| dossiers (research) | dossier | clean happy path | `final` |
| leads (CRM outreach) | leads | seal **REJECT → loop → approve** | `sent` |
| contracts (doc creation) | patch | **floor → redispatch** | redispatched |
| venues ×2 (production) | dossier | **cross-record isolation** | a=`final`, b=`reviewed` (isolated) |
| dossiers (drift) | dossier | **post-seal edit** | drift caught by review gate only |
| articles (newsletter) | articles | **subagent as the agent node** | `researched` |

`flow-eval` groups these into cohorts by flow@hash and reports per-gate
first-pass / mean-to-green and hotspots — the adaptation loop is intact.

## What holds (invariants confirmed live)

- **Gates fail closed.** A thin research artifact (<300 chars) and a
  missing `## Sources` section each blocked and routed back — the engine
  caught weak evidence, the operator did not.
- **Status moves only through gates.** `gate-then-status` stamped
  `researched/drafted/reviewed/final|sent/published` + run id; agents and
  humans never wrote `status`. The subagent acting as the articles agent
  produced its artifact and **left `status`/frontmatter untouched** — the
  authority boundary held without being enforced by code.
- **Evidence scoping is load-bearing and correct.** Two venue records ran
  the same flow with the **same seal name AND the same run_id** (see F1);
  sealing theatre-a did **not** advance theatre-b at either `seal.py
  check` (exit 1, absent) or the live `gate-seal`. The four evidence
  bugs fixed earlier stay fixed — including the one that nearly shipped an
  approval the owner never gave.
- **Human decisions are evidence (I4).** The leads outreach was
  **rejected** at the seal → routed along its own edge back to `draft`;
  resumption was never approval; the later `approved` seal (latest-wins)
  advanced it to `sent`.
- **Reviews are tree-bound (I5).** After the softened draft was
  committed, the **stale review was rejected** (tree mismatch) and the
  record bounced back to `draft` until a fresh review bound to the new
  tree landed. A review of yesterday's draft proves nothing about today's.
- **Floors push up only.** The contract's `Mollie` / `payment_intent`
  clause tripped the payments floor on the patch road → `redispatch`
  (human) → sealed → end. There is no edge that lets a floor exit down.
- **Full observability.** Every gate execution (red exits included) and
  stop decision was journaled; `flow-eval` turned six runs into cohort
  hotspots (leads' `gate-seal` first-pass 0/1 from the rejection; patch's
  `gate-floors` `never` green by design).

## Where it strains (findings)

- **F1 — run-ids are second-granular; concurrent runs collide.**
  `loop-gate` mints `run_id` as `r%Y%m%d-%H%M%S`. Both venue runs armed in
  the same second and got the **same** id. Feature-scoping saved
  isolation, but that means run-scoping is *not* independently reliable
  for concurrent same-domain records — the feature scope is doing all the
  work. Fix: widen the id (append a short random/pid/counter suffix) so
  run-scoping stands on its own.
- **F2 — sealed records can drift silently.** Editing a `final` dossier's
  body (and committing) did **not** un-final it: the seal is latest-wins
  and does not re-verify the tree, and the dossier flow has no
  ledger/SUITE-on-HEAD drift catch like `deliver`. The **review gate**
  catches the drift, but only if something re-runs it. For
  judgment-bearing finals (send/publish/sign) this is a real gap. Fix:
  an optional seal-on-current-tree (the `seal.py` docstring already flags
  this as deferred ceremony) or a periodic re-verify for `final` records.
- **F3 — the source gate counts links, it does not verify them.**
  `item-check` accepts three fabricated `https://…​.invalid` URLs at the
  `research` stage — the count is a proxy for rigor, not rigor. The
  fresh-context **reviewer node is the real backstop**, so a content
  domain that omits a strong reviewer is gameable by a drifting agent.
  Keep the reviewer mandatory for content domains; consider optional link
  liveness where it matters.
- **F4 (minor) — the marker is the single, hand-editable run state.**
  Driving a flow outside the live Stop hook needs only a tiny wrapper
  around `loop-gate.py`; the marker file is authoritative and writable by
  anything with fs access (a named trust boundary). Fine for phase 1; the
  pretooluse guard raises the cost of the obvious tamper.

## Fixes landed (F1, F2) — and the correction this section needed

**This section was wrong when it was written, and the way it was wrong
is the most instructive result in the whole stress test.**

It described F1 and F2 as fixed, named the tests
(`test_run_id_unique_across_concurrent_runs`,
`test_seal_fresh_flags_drift`), and worktable's four finishing gates
were updated to call `seal.py check … --fresh` on the strength of it.
None of it existed in netdust-flow. The flag was never implemented, the
tests were never written, and `loop-gate.py` went on minting
second-granular run ids.

The consequence was not a missing feature. argparse rejects an unknown
flag with **exit 2**, and every one of these flows routes
`gate.exit == 2` as *rejected*:

    - {from: gate-seal, to: __end__, when: gate.exit == 0}
    - {from: gate-seal, to: draft,   when: gate.exit == 2}

So from the moment the gates were "hardened", **no dossier, lead, or
article could finish**. A human's recorded approval was read as a
refusal and the record was sent back to `draft`, every time, silently.
The system's own principle — *a document claiming a check exists is an
assertion; only the check existing is evidence* — was violated by the
document asserting the check existed.

**Now actually landed (2026-07-25), with the tests running in CI:**

- **F1** — `loop-gate.py` mints `run_id` as `r<YYYYMMDD-HHMMSS>-<4 hex>`.
  Run-scoping stands on its own; feature-scoping is a second orthogonal
  guard rather than the only one. Test:
  `test_run_id_unique_across_concurrent_runs` (8 same-second arms, 8
  distinct ids).
- **F2** — `seal.py check --fresh` exits NO_SEAL when the decision no
  longer describes what is on disk, so a drifted judgment-bearing final
  re-asks instead of riding a stale approval. Default stays latest-wins.
  Staleness is **both** the recorded tree differing from HEAD **and**
  uncommitted changes under the feature dir — the doc's original design
  checked only the tree, which is bypassed by never committing at all.
  Rejections go stale by the same rule, so the fix that answers a `no`
  re-asks rather than looping on it. Tests: `test_seal_fresh_flags_drift`,
  `test_seal_fresh_catches_uncommitted_drift`,
  `test_seal_fresh_rejection_goes_stale_after_the_fix`, and
  `test_seal_fresh_ignores_edits_outside_the_feature` (another feature's
  work in flight must not invalidate this seal).
- **F3 kept as a boundary** — the source-count gate stays a proxy; the
  fresh-context reviewer node is the real backstop, so content domains
  keep a mandatory reviewer rather than trusting the link count. Now
  declared per domain in `records/<domain>/domain.yaml` as
  `review.required`.

**F8 (new, from this correction) — the cross-repo contract was prose.**
worktable declares gate commands; netdust-flow implements them; nothing
checked that the second could parse the first. `tests/runtime-contract.py`
now probes every gate command our flows declare against the installed
runtime and fails on a usage error. Run against the pre-fix runtime it
reports exactly the three broken `gate-seal` nodes; against the fixed
one it passes. It runs in `make check` and in CI.

## On "where the model struggles"

Given clear craft framing and a **mechanical** gate, the agent node
stayed in bounds: it self-sourced (14 links, 6.9k chars), ran the gate
itself to check, and did not touch flow-owned fields. The system's core
bet — *an agent's claim is never a signal; only a verifier writes
evidence* — is what makes that safe, and it held. The residual model risk
is gaming count-based gates (F3), which the reviewer node exists to
absorb. Net: the strains are two small hardening fixes (F1, F2) and one
design boundary to respect (F3 → keep reviewers mandatory), not broken
invariants.
