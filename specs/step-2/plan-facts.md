## 6. Harder than it reads

**6.1 The transition check and an expected `from` in `writes.ts`.** `valuesOf` (`writes.ts:317-339`) is the shared point: it has `op`, `ctx.current` (the live row, decoded) and the cut body, and is called by `runWrite` (`:381` via `storedOf`), `createAs` in actions (`actions.ts:68`), import (`import.ts:162`), seed-missing (`seed-missing.ts:54`) and undo's `restore` (`writes.ts:523`). It has no "mode" parameter: the undo inverse needs one (or `restore` passes a flag through `WriteContext`). An expected `from` cannot travel in the body: `cutBody` (`:75-77`) silently drops every key that is not a declared editable column, so a reserved key must be read in the route (`app.ts:47-51`) before `runWrite`, or a transition route added. `update()` is `WHERE id = ?` only (`:243-246`). `checkValues(dataset, cut, false)` runs before the writer (`:329`) and `checkOptions` after (`:335`), so an undeclared state is already 400 `bad_value` before any lifecycle code.

**6.2 Actions cannot create a child that points at a sibling created in the same batch.** `run` returns flat `{ dataset, values }[]` (`declare.ts:164`), and `createAs` creates them in order without feeding ids back (`actions.ts:72-73,65-73`). "Applying creates the open Toewijzingen in the same batch" needs an `activiteit_id` that does not exist when `run` returns. Either `run` returns nested creates (`{ dataset, values, then?: (id) => creates[] }` or `children`), or the engine creates in two passes. This is a second extension of `ActionDecl` beside F4's updates, and it is on the template task's critical path, not F4's.

**6.3 Public and header-authenticated routes in `app.ts`.** Order: Host check (`app.ts:155-160`), `basePath('/api')`, write guard on every write (`:165`), `publicRoutes` (`:166`), then `authRoutes` which registers `/auth/request` and `/auth/consume` and installs `sessionMiddleware` on `/*` (`auth.ts:189-193`). The middleware throws 401 when the cookie finds no account (`auth.ts:177-186`). Anything sessionless (`/record-links/request`, the action token's consume and projection) must be registered before `authRoutes`; a Bearer or RecordLink header must be handled inside `sessionMiddleware` (try the header, then the cookie) or by a middleware installed before it that sets `actor` and lets the session one skip when `actor` is set. `c.set('account', …)` is read by `/auth/me` (`:195`) and `accountOut` (`:55-58`), which assume an email.

**6.4 Projection and headers for owner views.** `publicRows` (`views.ts:344-361`) already projects to `visible_fields` minus the owner column and link keys and reads with scope `'all'`; the owner route is the same function with `scopeOf(actor, source)` and a key check against `owner_visible`. `/schema` serves `ColumnDecl` objects whole (`app.ts:96-97,192`), so `owner_visible` reaches the grid for free; `EngineColumn` (`engine.ts:6-20`) ignores unknown keys. Response headers today: only `X-Content-Type-Options` on the root (`app.ts:156`); the three owner headers go on a sub-app or in each handler.

**6.5 `may()` and the route matrix.** `ALLOWED` is `Record<Surface, Role[] | 'anyone'>` (`access.ts:21-32`) keyed on role only; adding `kind` means a second table or a predicate, and `Actor` (`declare.ts:144-148`) gains `kind`, which every writer's `ctx.actor` then carries (harmless, but `Actor` is exported to domains, `index.ts:4-21`).

**6.6 `whose()` and `accountOut()` assume an email** (`history.ts:122-124`, `auth.ts:55-58`); both need the `name` and the link subject.

**6.7 The vocabulary check will fail on `aantal`** the moment theatre declares it: the engine fixture has a column `aantal` (`test/fixture.ts:111`) and `test/matrix.test.ts` or others may name it; allowlist it in `scripts/vocabulary-allow.txt` or rename the fixture column in the first task. `rol` is safe (engine says `role`; words split on non-letters, `check-vocabulary.ts:31-35`).

**6.8 Undo of a create whose writer has no delete is 405** (`test/batches.test.ts:170`, `writes.ts:495`): a fill action that creates a Toewijzing is undoable only because the Toewijzing writer has `delete` (`writers.ts:154`); the action token table and `record_link` are engine tables and never reach `touchedBy`'s domain lookup (`writes.ts:475-476`).

**6.9 The matrix store and the engine disagree on who owns undo.** The store reverses its own ops by re-sending writes (`store.ts:352-370`); an action's effects (a split: one update plus one create) can only be reversed by `POST /batches/:id/undo`. The fill must bypass the op stack and push the batch onto the tab history (`App.tsx:176`), or the matrix's Ctrl+Z will try to "update" a row it never wrote.

**6.10 `--outbox` and hostname.** `serve.ts:259-262` refuses any hostname but loopback because there is no mailer; `--outbox` creates the dir with mode 0700 (`:383`); `deliver()` writes files with 0600 (`auth.ts:109-110`). The Mailer interface replaces `deliver()`'s file write and the `console.log` at `auth.ts:111`; `test/sign-in.ts:22-32` and `e2e/auth.ts:57-67` parse the outbox file format (`To: <email>\n\n<link>\n`), so keep it or update both readers.
